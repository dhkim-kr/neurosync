# EvidenceVerifierAgent

> **Role**: Verify that all claims in the Handoff Report are evidence-grounded and free of diagnostic/treatment assertions
> **Model Policy**: Benchmarked (Solar Pro 3 / K-EXAONE / A.K) + Rule Checker
> **System Prompt**: `docs/ai/prompts/evidence_verifier/v1.system.md`
> **Implementation**: `apps/ai-server/src/agents/evidence_verifier.py`

## Input

| Field | Type | Required | Description |
|---|---|---|---|
| draft | string | Yes | The Handoff Report draft markdown generated by HandoffGeneratorAgent |
| evidence_packets | list[object] | Yes | Evidence packets used during report generation, each with `evidence_id`, `source_type`, `source_id`, `timestamp`, `content`, `metadata` |

## Output

| Field | Type | Description |
|---|---|---|
| verified_report | string | The verified Handoff Report markdown (unchanged if all claims pass, or with flagged/removed claims) |
| flags | list[object] | Verification flags, each with `claim_text`, `flag_type` (one of: `unsupported_claim`, `diagnostic_assertion`, `treatment_directive`, `missing_evidence`, `low_confidence_source`), `severity`, `recommendation` |
| pass | bool | Whether the report passed verification (no critical flags) |
| requires_human_review | bool | Whether clinician review is required due to flagged issues |

## Behavior

1. Receive the Handoff Report draft and the evidence packets used during generation.
2. Run two verification processes **in parallel**:
   - **Rule Checker**: Scan for prohibited patterns (diagnostic assertions, treatment directives, medication adjustment language).
   - **LLM Evidence Verifier**: For each core claim in the report, verify that a matching evidence ID exists and the claim is supported by the evidence content.
3. Flag any claims that:
   - Have no supporting evidence ID (`unsupported_claim`).
   - Assert a diagnosis (`diagnostic_assertion`).
   - Recommend or direct treatment/medication (`treatment_directive`).
   - Reference a low-confidence OCR source without a `needs_review` annotation (`low_confidence_source`).
4. If any `unsupported_claim` is found:
   - The report is **rejected** (`pass = false`).
   - HandoffGeneratorAgent must regenerate or remove the unsupported claims.
5. Return the verified report with flags and pass/fail status.

## Safety Constraints

- Must catch all unsupported claims; false-negative unsupported claim rate must be minimized.
- Must never allow diagnostic assertions or treatment directives to pass verification.
- Must never modify evidence IDs or claim content during verification (read-only analysis).
- Must flag low-confidence OCR-sourced claims that lack `needs_review` annotations.
- Verification results must be stored for audit and clinician review.

## Failure Fallback

When the Evidence Verifier LLM fails (timeout, invalid response, 5xx):
- Mark the entire report as **clinician-review required** (`requires_human_review = true`).
- The Rule Checker result alone is used for basic pattern-based verification.
- The report is delivered to the clinician dashboard with a prominent review-required flag.
- Log the failure with `agent_trace_id`, `model_used`, and `latency_ms`.

## Model Selection

ModelRouter queries `agent_model_registry` for `agent_name=evidence_verifier`. Selection criteria:
- **Priority metric**: False-negative unsupported claim rate (lower is better).
- Candidates: Solar Pro 3, K-EXAONE, A.K.
- The model with the lowest false-negative rate is selected as Primary.
- Fallback chain: timeout / 429 / 5xx / evidence_verification_failed triggers clinician-review-required fallback.

## Dependencies

- **HandoffGeneratorAgent**: Provides the draft report and triggers verification.
- **TemporalRetrieverAgent**: Provides the evidence packets for cross-reference.
- **Rule Checker**: Internal module for pattern-based prohibition detection.
- **ModelRouter**: Selects the model for evidence verification.
- **Clinician Dashboard**: Receives the verified report with review flags.
